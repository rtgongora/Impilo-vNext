# Experience Completion Packs

The Target Architecture registers seven completion packs. These folders are intentionally placeholders until each full-depth blueprint is created from measured repository evidence.

1. P1 - Public, My Life and My Professional
2. P2 - Provider, Organisation, Facility and Node Self-Service
3. P3 - Clinical Work Experience
4. P4 - Regulatory and Oversight
5. P5 - Accessibility, Localisation and Content
6. P6 - Design System and Component States
7. P7 - Human Usability and Field Validation

**Ordering (Target Architecture v1.3.2 §42, binding):** the packs are not produced 1→7. **P5, P6 and P7 are cross-cutting and start immediately** — every journey pack is produced *through* them. Functional priority follows the Hospital Node delivery target: the encounter-context correction (§42.2) → P3 → P2 → P1 ∥ P4. Until architecture freeze, all packs are drafted as **non-controlling** documents; they become controlling implementation specifications only after freeze (see the Implementation gate in the Target Architecture).

No journey is considered implementation-ready until its full blueprint defines actors, entry, screens, decisions, data, validation, authority transitions, persistence, failure, recovery, offline behaviour, notifications, audit, Nompilo behaviour, web/mobile parity and acceptance evidence.
