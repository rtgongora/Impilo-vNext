# MusheX / COSTA outbox event catalogue

> **Purpose.** A single source of truth listing every Kafka outbox event type that MusheX or COSTA emits, the topic it lands on, the originating service, the aggregate type, and (where unambiguous) the known payload-shape keys.
>
> **Authoritative source.** This catalogue is generated by reading two source-of-truth points in the codebase: the `routeTopic(...)` switch in each service's `OutboxPublisher.java`, and the `publishEvent(...)` call-sites. When either source changes, this catalogue must be updated in the same batch.
>
> **Scope.** Definitional. This document does not configure consumers, dashboards, or alerts.

### MusheX call-sites known to use the default `mushex.events` topic

The following event types are produced but **not** routed to a dedicated topic — they fall through to the default `mushex.events`. This is documented here so a future Slice 8B (convention test) can flag them.

- `CLAIM_DISPUTED`
- `SETTLEMENT_COMPUTED`
- `REMITTANCE_REVOKED`
- `LEDGER_ENTRY_POSTED`
- `RECON_MATCHED`

A reviewer adding a new dedicated topic for any of the above must update both the `routeTopic` switch and this catalogue in the same change.

## 4. How to keep this catalogue current

- **When adding a new `publishEvent(...)` call-site:** add a row to § 1 or § 2 in the same change. If you also added a dedicated topic, update `routeTopic(...)` and the relevant table here.
- **When renaming an event type:** update the row and the `routeTopic(...)` switch in the same change. Renaming an existing event type is a contract change; coordinate with consumers.
- **When deleting an event type:** keep the row but mark it as `retired-on-YYYY-MM-DD` so historical consumers can still resolve the type.
