## Wave R1 — Journey unblockers (G1 inpatient, G5 teleconsult Stage-4)

### G1 — Inpatient admission, bed assignment, ward-round recording

**Scenario.** Dr Rudo Moyo (Chitungwiza Central) closes an encounter with Visit Outcome → Admit for a decompensated-heart-failure patient. Today the button dead-ends on `/beds` (status toggles only) and the admission goes to a paper register. Post-fix: a pre-filled New Admission form (CPID + encounter), live bed picker, one atomic submit → admission created + bed OCCUPIED + episode dashboard; consultant records morning ward rounds; the already-wired discharge closes the loop. **Edges:** no free bed (honest census counts, no half-created admission); bed-safety violation (gender-bay mismatch → structured 400 surfaced, nothing written — requires the BedController honesty fix); patient already admitted (pre-submit `useActiveAdmission` guard linking to the open episode); inpatient-service down (502 rendered, form state preserved).

**Fix design.**
1. **BFF honesty fix (prerequisite):** rewrite `services/experience-bff/.../controller/BedController.java` `assignPatient`/`updateBedStatus`/`dischargeBed` to propagate upstream status/error payloads (mirror `InpatientController`'s `upstreamFailure` pattern) instead of catch-log-fabricate; `listWards`/`listBeds` return 502 on failure, not silent empty lists.
2. **Atomic engine change (inpatient-service, same service+DB):** `AdmissionService.createAdmission` with `bedId` present calls `BedManagementService.assignPatient` **inside the same `@Transactional` boundary**; safety violations abort the whole admission with structured 400/409. Allow RESERVED→OCCUPIED assignment (one-line follow-on) so the beds page's Reserve action doesn't sabotage admits.
3. **UI:** new `ui/one-ui-shell/src/app/clinical/inpatient/admissions/new/page.tsx` + `components/inpatient/NewAdmissionForm.tsx` (fields 1:1 with `CreateAdmissionRequest`; pre-submit active-admission guard) + `BedPickerField.tsx` (ward tabs, AVAILABLE-only selectable, RESERVED visible-disabled, honest empty states). Rewire three dead entry points: admissions list "New admission", `ehr/[patientId]/discharge` ADMIT panel, `InpatientAdmissionHandoffBanner`. Beds page gains an "Admit here" deep-link for AVAILABLE beds when handoff params present.
4. **Ward rounds:** new `useStartWardRound()`/`useAddWardRoundEntry()` hooks (BFF routes exist: `CareEmergencyInpatientController POST /ward-rounds`, `/{id}/entries`) + `WardRoundRecorder.tsx` on the episode page; rounds page replaces its "first admission only" hack with an admission selector.
5. **Audit:** BFF emits `INPATIENT_ADMISSION_CREATED` / `INPATIENT_BED_ASSIGNED` (reference: `TelemedicineGovernanceService.audit`).

**Decisions:** dedicated `/admissions/new` route with three entry points; atomic engine change over UI-orchestrated two calls (split-brain risk); BedController fake-success fixed in-wave (wiring a UI to a lying endpoint is strictly worse than a dead button); PCT decision-workflow (journeys/{id}/admit → approve) surfacing deferred as explicit follow-up (zero BFF plumbing today; the Kafka handshake keeps working); duplicate-admission guard UI-first, engine unique-active constraint flagged.

**Acceptance:** clinician admits from encounter close without leaving the flow; bed renders OCCUPIED from live data; unsafe/occupied bed → visible error, zero rows written; duplicate blocked with episode link; ward round + entry recorded and listed; discharge completes the loop; service-down → explicit failures; **new honest e2e creates the admission through the UI** (`e2e/inpatient-admit-to-discharge-honest.spec.ts`, unique CPID per run) — existing specs relabelled as rendering-contract tests (they mock/seed and must stop implying journey coverage).

**Commits (7):** BedController honesty → atomic admission+bed engine → admission form+picker page → entry-point rewires → ward-round wiring → BFF audit emits → honest e2e + relabels. **Size M overall.**

### G5 — Teleconsult Stage-4 governed specialist accept/decline

**Scenario.** Dr Chipo Nyathi (dermatology, virtual specialist pool) opens her teleconsult worklist, reviews a rural referral package, Accepts → governed route fires (`assertGovernedMutate`, PCT `SUBMITTED→ACCEPTED`, `TELEMEDICINE_REFERRAL_ACCEPTED` audit, `TELECONSULT_ACCEPTED` notification to the referrer) → proceeds to the Stage-5 session. **Edges:** decline requires a mandatory reason (today the BFF silently defaults blank reasons — an audit-integrity hole; fixed with 400 `DECLINE_REASON_REQUIRED`); governance rejects a non-governed actor; accept race (no FSM CAS in PCT — UI refetch + show `acceptedBy` now, engine CAS flagged for R5); PCT down → retryable error, no phantom acceptance.

**Fix design.** Do **both** surfaces cheaply (endpoints + hooks largely exist): (1) BFF `accept` gains an optional body passing through `receiving_facility_id`/`receiving_facility_name`/`scheduled_at`/`notes` (PCT persists receiving facility — 3-line change); `decline` rejects blank reason with 400. (2) New `useAcceptTeleconsultSession`/`useDeclineTeleconsultSession` hooks. (3) `queue/incoming-referrals/page.tsx` detects teleconsult rows via `attrs.modality === "virtual"` (already round-trips), badges them, routes Accept/Decline through the governed hooks; same detection migrates `ehr/[patientId]/consults` (another governance bypass one click away). (4) New specialist worklist `work/telemedicine/worklist/page.tsx` on the already-governed `useTelemedicineSpecialtyWorkbench` hook (spec worklist types 2+6): urgency, waiting time, origin facility, package review, Accept/Decline, "Go to session".

**Decisions:** both surfaces; `modality==="virtual"` now, `referral_type=TELECONSULT` as R5 hygiene; decline stays teleconsult-only; server-side reason enforcement; accept-race CAS deferred to R5 (mobile `/join` alias implications).

**Acceptance:** worklist → review → Accept flips PCT to ACCEPTED with audit + notification; Decline requires reason server-side; e2e intercepts prove teleconsult rows hit `/teleconsult/sessions/{id}/accept` while plain rows still hit `/referrals/{id}/accept`; acceptance context persisted; non-governed actor fails visibly; "Go to session" closes the 1→7 chain. New honest e2e creates its own referral (`e2e/teleconsult-stage4-accept.spec.ts`).

**Commits (6):** BFF accept-context+decline-validation (+the missing unit tests) → PCT receiving-facility persistence → hooks → incoming-queue/consults migration → worklist page → e2e. **Size S–M.**

## Wave R3 — Coverage subsidy (G3 → G2 → G15)

**Winner: single-L `cv_subsidy_enrolments` (V010/V011)** — it owns the H1 atomic conditional-UPDATE cap, H2 idempotent drawdown ledger (`UNIQUE (enrolment_id, reference)` + compensating negate), cap overrides, eligibility `checkCap()`, and 10 tests. The double-L V012 table contributes exactly one scalar — `exemption_category` (drives COSTA exemptions via `resolvePatientCategory`) — which is absorbed.

**Scenario.** Sister Chipo Marufu enrols Mrs Ncube in `SUB-DONOR-MATERNAL` ($3,000 cap, MATERNITY category). Today the fork is invisible: the enrollments path gives the billing category with **no cap tracking**; the enrolments path enforces the cap but **COSTA never sees the exemption**. Post-fix one row does both. **Edges:** member enrolled through both routes pre-fix → migration merges to exactly one ACTIVE canonical row; ENDED history carries status + `effective_to` so category resolution correctly falls through; stale-JAR redeploy → rename-not-drop posture makes an old binary fail loudly.

**Design:** `V013__subsidy_model_reconciliation.sql` — add nullable `exemption_category` to `cv_subsidy_enrolments`; merge/insert V012 rows (dedupe on tenant+program+member overlapping-ACTIVE); **rename** `cv_subsidy_enrollments` → `zz_..._deprecated` (drop in a later hygiene wave). Rewire `CoveragePlanController.resolvePatientCategory` onto the canonical repository (same response contract — BFF/COSTA untouched). Retire the double-L entity/repo/DTOs/routes; keep a one-wave `@PostMapping({"/enrolments","/enrollments"})` alias serving the canonical DTO; add `POST /enrolments/{id}/end`. **Acceptance:** one row answers both cap and category; no member's billing category changes; fresh-DB (V001→V013) and existing-DB boots both green; the 10 cap/idempotency tests + rewired `PatientBillingCategoryResolutionTest` green.

### G2 — Wire the subsidy lane (BFF + UI + events; ~2.5–3 days, strictly after G3)
