# Core Transaction Acceptance Criteria

Every feature must answer all criteria before being considered aligned.

1. Which Core Transaction type does it support?
2. Which lifecycle stage does it support?
3. Which actor does it serve?
4. Which Person Journey stage applies, if any?
5. Which Provider Journey stage applies, if any?
6. Which Platform Journey stage applies?
7. Which plane owns source truth?
8. Which service owns the data?
9. Which state is created/read/updated/closed?
10. Which event is emitted?
11. Which permission or consent rule applies?
12. Which audit event is generated?
13. Which UI surface exposes it?
14. Which BFF/contract wires it?
15. Which tests prove it?
16. Which analytics/reporting learns from it?
17. Which offline/federated behavior applies?
18. What is failure behavior (identity/consent/payment/connectivity/sync)?
19. How does it improve access, delivery, continuity, accountability, accessibility, or intelligence?
20. Does it create duplicate domain truth?
21. Does it preserve person-centered continuity?
22. Does it reduce provider burden?
23. Does Nompilo need to assist/guide/explain/handoff/collect feedback here?
24. What accessibility needs are relevant?
25. What omnichannel feedback opportunity exists?
26. Does it help the health system act better?
