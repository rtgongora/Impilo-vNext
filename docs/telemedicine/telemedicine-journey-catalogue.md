# Telemedicine Seven-Stage End-to-End Journey Catalogue

Companion to [Volume I — National Telemedicine & Virtual Care Specification](NATIONAL_TELEMEDICINE_VIRTUAL_CARE_SPECIFICATION.md) (§28), [Volume II — National e-Orders, Fulfilment & Telemonitoring Specification](NATIONAL_EORDERS_FULFILMENT_TELEMONITORING_SPECIFICATION.md) (§23) and the [backlog](telemedicine-implementation-backlog.md). One catalogue serves the whole pack: #1–#40 are the Volume I (telemedicine) journeys; #41–#70 are the Volume II (order-to-outcome, fulfilment, telemonitoring) journeys. Each journey is a runtime-provable scenario: **a green frontend mock is never proof** — proof means live-estate execution with UI, state, API, event, SHR, audit and notification assertions plus explicit failure criteria.

**Provable-today legend:** ✅ proven (existing script/spec named) · 🟢 provable now (assets exist, scenario unscripted) · 🟠 partially provable · 🔴 blocked on backlog epic (named).

**Common preconditions (all journeys):** full preview estate; seeded personas (`dr.mapfumo` provider, `nurse.chienda` accepting clinician, `citizen.moyo` or VITO-registered patient); reconciled Keycloak; scenario-A seed state (`docs/journeys/scenario-a-clinical-journey.md`). Standard failure criteria (all journeys): any silent state skip; any case stranded invisible; any PHI in an external notification or log; any media token before admission; any completion without a note.

### Test-class coverage requirements (Volume II additions)

Volume II journeys bind to the same §28/Vol II §23 minimums (happy-path live e2e, every named negative, state-transition asserts against §9, exact event names, audit presence) and add four classes the Volume I set does not exercise: **payment idempotency** (#41, #48, #70 — duplicate intent submission and retry-after-timeout must produce exactly one PAID fact and one refund where due), **custody integrity** (#42, #43, #67, #68 — the custody chain must be gap-free across mode changes and failed attempts, with excursion events unsuppressible), **device-telemetry replay** (#59, #62, #64 — replayed and duplicated readings must be idempotent at ingest AND at the single SHR writer, with quarantine never silently dropping), and **clock-skew** (#55, #59, #64 per §22.7 — offline-captured dispenses and readings with skewed device clocks must be time-corrected with provenance or quarantined, never silently re-timestamped).
