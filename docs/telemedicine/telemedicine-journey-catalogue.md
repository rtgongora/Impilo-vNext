# Telemedicine Seven-Stage End-to-End Journey Catalogue

Companion to the [National Telemedicine & Virtual Care Specification](NATIONAL_TELEMEDICINE_VIRTUAL_CARE_SPECIFICATION.md) (§28) and [backlog](telemedicine-implementation-backlog.md). Each journey is a runtime-provable scenario: **a green frontend mock is never proof** — proof means live-estate execution with UI, state, API, event, SHR, audit and notification assertions plus explicit failure criteria.

**Provable-today legend:** ✅ proven (existing script/spec named) · 🟢 provable now (assets exist, scenario unscripted) · 🟠 partially provable · 🔴 blocked on backlog epic (named).

**Common preconditions (all journeys):** full preview estate; seeded personas (`dr.mapfumo` provider, `nurse.chienda` accepting clinician, `citizen.moyo` or VITO-registered patient); reconciled Keycloak; scenario-A seed state (`docs/journeys/scenario-a-clinical-journey.md`). Standard failure criteria (all journeys): any silent state skip; any case stranded invisible; any PHI in an external notification or log; any media token before admission; any completion without a note.

## Test-class coverage requirements

Every journey binds to the §28 test classes; minimum per journey: one happy-path e2e (live estate), every named negative path, state-transition assertions against §11.3, event-contract assertions (exact names), and an audit-presence check. Concurrency journeys (#17, #18, #35) additionally require race harnesses; offline journeys (#15, #16, #34) require replay/idempotency property tests; media journeys (#11–#14) require real-browser WebRTC with fake devices and TURN-fallback variants.
