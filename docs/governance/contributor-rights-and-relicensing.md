# Contributor Rights and Relicensing

## Purpose

Impilo vNext is being developed in a repository that is proprietary by default. That makes contributor-rights discipline essential if any subprojects are later extracted under Apache 2.0 or another licence.

## Practical Position

- relicensing and dual/commercial licensing require clean rights management
- contributions to this repository are accepted subject to the repository's proprietary posture unless otherwise documented
- if later extraction or relicensing is planned, contributor agreements, assignments, or equivalent rights-management controls may be required

## Why This Matters

Future Apache 2.0 extraction is only straightforward when the rights holder has a clean legal basis to grant that licence. If contribution rights are unclear, later relicensing becomes risky, slow, and potentially blocked.

## Operating Guidance

### For Repository Maintainers

- keep the repository's legal posture explicit
- avoid implying open-source rights where none have been granted
- track which areas are intended for future extraction
- ensure any future relicensing decision is supported by documented rights ownership

### For Contributors

- contributions are made into a proprietary repository unless a narrower licence grant is explicitly documented for a specific extracted artefact
- contributors should not assume that code contributed here is open source
- if a later extraction is planned, contributors may be asked to sign an assignment, CLA, or similar rights-management instrument

## Relicensing Readiness

Before any extracted artefact is published under Apache 2.0 or another licence, the project should confirm:

1. the artefact is actually separable from proprietary platform logic
2. the repository history for that artefact has clean contribution provenance
3. the rights holder can grant the intended licence cleanly
4. third-party dependencies and embedded assets are compatible with the intended licence

Unless and until a specific artefact is explicitly relicensed, the default assumption remains:

> **Contributions land into a proprietary repository and do not create an implied open-source grant.**
